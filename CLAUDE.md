## Коннектор к Obsidian (база знаний Claude)

Знания живут в **одном месте** — Obsidian-vault `Pedro78`, папка `claude-kb/`.

- **MCP-сервер:** `obsidian`, префикс путей — `Pedro78/`.
- **Vault на диске:** `<OBSIDIAN_VAULT>`.
- **База знаний (единая точка):** `Pedro78/claude-kb/`.
- **Точка входа:** `Pedro78/claude-kb/INDEX.md` — **читать первой** при работе со знаниями.

### Что внутри `claude-kb/`

| Путь | Назначение |
|------|-----------|
| `claude-kb/INDEX.md` | Точка входа (коннектор). Карта базы + как ею пользоваться. |
| `claude-kb/raw/`  | **Сырые, непроверенные данные.** Выгрузки, прогоны, черновики, гипотезы, находки. Дёшево добавить, проверять необязательно. |
| `claude-kb/wiki/` | **Зафиксированный канон.** Только подтверждённое: решения, проверенные числа/формулы, утверждённая механика. Источник истины. |
| `claude-kb/CLAUDE.md` | Правила потока raw↔wiki (vault-сторона). |

### Как пользоваться
1. **Чтение:** открыть `claude-kb/INDEX.md`; источник истины — `wiki/`; `raw/` — справочно.
2. **Запись:** находка/прогон/идея → `raw/`; подтверждённое → промоут в `wiki/`.

### Поток данных

```
источник / прогон / идея  →  raw/  →  (проверка)  →  wiki/  →  репозиторий
```

- **код → Obsidian:** подтверждённые данные фиксировать в `wiki/`; сырое — в `raw/`.
- **Obsidian → код:** `wiki/` — источник истины; отражать в `docs/` и код.
- Канон по механике ЗРД дублируется в `docs/zrd-wiki/`. **При расхождении с vault `wiki/` — синхронизировать, не плодить две версии правды.**

### Правила
- Данные из `raw/` не истина, пока не проверены и не перенесены в `wiki/`.
- Промоушен raw → wiki только когда данные подтверждены (тест / решение / число зафиксировано).
- В `wiki/` соблюдать стандарт frontmatter vault и «≥1 wikilink».
- Удаление/переименование/перенос заметок в vault — только с подтверждения пользователя.

Подробные правила: `Pedro78/claude-kb/CLAUDE.md`. Конституция vault: `Pedro78/CLAUDE.md`.

## Штаб Claude

Работа по SimCenter идёт штабом Claude: управляющий, аналитик, редактор, проверяющий (профили в `.claude/agents/`). Правила, маршруты и границы — `docs/project/claude-headquarters.md`. Модели ChatGPT (Luna, Sol, Astra, Codex) в этой работе не используются; Файлы прежней схемы оркестрации и блок про неё в `AGENTS.md` не правятся без поручения; автоматика в её настройках отключена 02.11.2026. Каждый проверенный коммит сразу отправляется на GitHub в ветку `claude/<тема>-<дата>` (порядок — в разделе 5 `docs/project/claude-headquarters.md`). PR, слияние, выкладка и удаление — только по «да» владельца на каждое действие. Изменения по проекту обязательно записываются в `01-projects/simcenter/WORKLOG.md` в Obsidian (разрешено владельцем 02.11.2026); секреты и сырые данные участников туда не переносить.

Порядок работы штаба (читать до любой задачи, кроме короткого вопроса):

1. Назвать маршрут из раздела 3 `docs/project/claude-headquarters.md` (question, analysis, engineering, content, methodology, knowledge) и в начале ответа сказать владельцу: маршрут, кто что делает, кто проверяет.
2. Профили `analyst`, `editor`, `reviewer` из `.claude/agents/` в среде Claude могут не регистрироваться как агенты. Если среда их не видит, запускать обычного агента (general-purpose): передать ему текст профиля роли и только нужные входы. В отчёте писать прямо: «имитация профиля, не штатный запуск; права «только чтение» не гарантированы». Штатный запуск профилей не проверялся.
3. Проверяющий — всегда отдельный агент, принимает только хеш локального коммита. Проверка самого автора независимой не считается.
4. У `analyst` и `editor` нет сети. Поиск в сети ведёт управляющий и передаёт найденное со ссылками.
5. Нужен исполнитель вне трёх профилей: новый профиль не создавать, а задать специализацию в назначении. Новый технический профиль — только по решению владельца; сначала написать ему, зачем он нужен.
6. В итоге сообщать: маршрут, кто что делал, что проверено отдельным агентом, что не проверено. Работу без агентов, когда маршрут их требовал, не скрывать.

Материалы по симуляции вне репозитория: папка `<PROJECTS_DIR>/Simulacia` и соседняя папка с идеей и презентацией, в Obsidian — `01-projects/simcenter/` и `claude-kb/wiki/simcenter/`. Что в них и что в архиве — в `README.md` самой папки Simulacia. Это справочные материалы со своей датой, не источник рабочего кода. Файлы `data.db` и `live-sessions.json` без поручения не открывать.

## Редактор смысла — text-editor-ru 1.0.0

Для текстовых задач и финальной редактуры материалов проекта используй `text-editor-ru`: перед применением прочитай `.claude/skills/text-editor-ru/SKILL.md`, справочники загружай по необходимости. При просьбе только проверить исходник не переписывай. В обычных вопросах и задачах без текста отдельный редакторский проход не запускай.
В этом проекте это основной текстовый редактор. Не подключай `humanizer` или `humanizer-ru` параллельно либо последовательно без отдельной просьбы пользователя; существующие навыки не удалены.
Сначала проверка содержания, затем редактура, затем сверка смысла. Сохраняй числа с единицами, периоды, группы сравнения, источники, условия, оговорки, исполнителей и статус решений. Не добавляй факты и поручения ради гладкости текста.
Правила проекта о данных, жанре и оформлении сохраняют силу. Не меняй код, формулы, данные графиков, таблицы, легенды, меню и макеты под видом редактуры. Полезные списки, выделения и авторскую прямоту сохраняй.
Установка не разрешает отправку сообщений, выпуск новостей, развёртывание или обработку уже готовых документов без поручения. Для новостных материалов сохраняй отдельные правила сбора источников и согласования публикаций.
