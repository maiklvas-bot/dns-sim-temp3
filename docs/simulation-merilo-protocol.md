# Протокол расчёта «мерила» (симуляция «Космонавт»)

> **Пред-регистрация.** Зафиксирован **до** прихода ответов опроса (согласован 2026-07-12, ответы
> ждём ~2026-07-17). Смысл: правила расчёта объявлены заранее — веса нельзя «подогнать под
> результат». Это прямая защита от отторжения управляющих («веса кривые»), с которого началась
> задача.
>
> Связано: [анкета](simulation-survey-criteria.md) · [профиль выпускника](kosmonavtika-graduate-profile.md)
> (14 компетенций) · [методология ТЗ-0](simulation-case-validation-tz.md) (G3, разделы 12/14/18) ·
> скоринг `shared/simulation-scoring.ts`.

## Что на входе
Ответы опроса по секциям: 1 профиль · 2 критические инциденты · 3 веса (100 баллов по блокам +
важность 1–5 в сетках + 3 стоп-фактора) · 4 якоря по топ-3 · 5 реакции руководителя.

## Что на выходе (мерило)
1. **Таблица весов** 14 компетенций (сумма 100) + флаг согласия + подсвеченные вылеты.
2. **Список стоп-факторов** + порог срабатывания.
3. **Якоря поведения** (BARS): 3 уровня на компетенцию.

---

## Шаг 1. Вес компетенции у одного управляющего (решение №1 — вариант A)

Для управляющего `r`, компетенции `c` в блоке `B`:

```
w_r(c) = БаллыБлока_r(B) × важность_r(c) / Σ важностей всех компетенций блока B
```

Учитывает оба сигнала анкеты (вес блока × доля важности внутри). Веса одного управляющего в сумме
дают 100.

## Шаг 2. Свод по всем управляющим (решение №2 — усечённое среднее + подсветка вылетов)

Для каждой компетенции `c`, по всем ответившим:
1. Выстроить значения `w_r(c)` по возрастанию.
2. **Отбросить одно минимальное и одно максимальное.**
3. Итог `W(c)` = среднее оставшихся.
4. **Отброшенные крайние значения + кто их поставил → всегда в отчёт**, с флагом «посмотреть глазами»
   (вылет молча не теряем — за ним может стоять важное).
5. **Финальная нормировка:** после независимого усечения по 14 компетенциям сумма ≠ 100 —
   пропорционально масштабируем все `W(c)`, чтобы сумма снова была 100.

## Шаг 3. Мера согласия (решение №3 — коэффициент вариации, CV)

Для каждой компетенции считаем `CV(c) = стандартное отклонение / среднее` (по **полному** набору
ответов, включая вылеты — чтобы разногласие было видно):
- `CV ≤ ~0.30` → **согласие**, вес твёрдый.
- `CV ≥ ~0.50` → **«спорная, на обсуждение»**: вес предварительный + флаг, нужно решение человека.
- между → умеренное согласие, пометка.

Точные пороги (0.30 / 0.50) **калибруются на реальном распределении** ответов 17-го; здесь
зафиксирован сам механизм, не финальные цифры.

## Шаг 4. Порог доверия по числу ответов (рекомендованный дефолт — подтвердить)

- `n ≥ 8` → веса твёрдые.
- `5 ≤ n ≤ 7` → считаем, помечаем «предварительно».
- `n < 5` → **не фиксируем**, продлеваем сбор / напоминание.

*(Единственный пункт, не подтверждённый явно в диалоге — правь, если планка другая.)*

## Шаг 5. Стоп-факторы (решение №4 — мягкое вето)

**Определение:** компетенция — стоп-фактор, если её отметило **большинство** управляющих (> n/2).
Если ни одна не набрала большинства → берём топ-3 по частоте и выносим на подтверждение.

**Механика — мягкое вето:**
- Симуляцию **не останавливаем**, участник проходит полностью.
- Если балл участника по стоп-фактору **ниже порога** `θ` (ориентир: < 2 из 5) → **красный флаг**.
- В итогах красный флаг подсвечивается как **блокирующее условие для дальнейшего развития**
  (не «незачёт», а «путь наверх закрыт, пока не закрыто это»).
- **Обязательные следствия красного флага** (сверх обычных выводов):
  1. **Углублённый разбор** этой компетенции на **дебрифе**.
  2. **Детальный план мероприятий** с **повторной проверкой**, что западающий навык/знание налажены.

**Зависимость:** пункты 1–2 требуют слоя **дебриф + ИПР/план закрепления**, которого в движке
сейчас нет (разрыв G6 ТЗ-0). ⇒ Пересборка **обязана** его построить. Порог `θ` — уточнить/калибровать.

## Шаг 6. Якоря поведения — BARS (решение №5)

- **3 уровня** на компетенцию: **слабо / средне / сильно** (наблюдаемое поведение).
- **Материал:** секция 4 (якоря по топ-3) **+ секция 2** (критические инциденты — их заполнили все,
  покрывают компетенции вне топ-3).
- **Процесс:** черновую группировку формулировок в уровни делает Claude → **финал утверждает
  пользователь**. Компетенции с малым числом ответов помечаются «якорь предварительный».

Пример («Мотивация сотрудников»): *слабо* — давление/обезличенно; *средне* — формально по шаблону;
*сильно* — опора на индивидуальный мотив. Эти строки автор кладёт в варианты ответа кейса.

## Куда идёт результат
- **Веса** `W(c)` → `SimulationScoringSettings` в `shared/simulation-scoring.ts` (замена «выставленных
  на глаз» весов на выведенные из ответов управляющих).
- **Якоря** → опора авторам при написании `CaseOption` (какой вариант какой уровень поведения).
- **Стоп-факторы + красный флаг** → правило-гейт поверх суммы весов + требования к дебрифу/ИПР.
