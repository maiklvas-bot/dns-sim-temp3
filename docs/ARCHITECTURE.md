# Architecture

The project is a TypeScript full-stack application:

- Frontend: React 18, Vite, Tailwind CSS, TanStack Query.
- Backend: Express, TypeScript, SQLite.
- Shared contracts: TypeScript types and schema definitions in `shared/`.
- Runtime: Docker container with persistent bind mounts for SQLite data and uploads.

Main request flow:

1. Browser loads the Vite-built frontend from the Express server.
2. Frontend calls `/api/*` endpoints for auth, content, sessions, admin settings and results.
3. Backend reads/writes SQLite through storage modules.
4. Live simulations are coordinated through backend live-session services and frontend polling/state sync.
5. PDF reports are generated by the backend PDF generator from normalized report payloads.

Frontend module boundaries:

1. Files in `client/src/pages/` only expose route entrypoints.
2. Product workspaces live under `client/src/features/admin`, `assessor` and `simulation`.
3. Simulation business state is exposed through the compatibility context path, while its implementation lives in `features/simulation-engine`.
4. Pure scheduling, timer and setup utilities do not render React UI.
5. Domain CSS is loaded in an explicit order from `client/src/main.tsx`; new large style blocks must not be added to `client/src/index.css`.

Security baseline:

- staff login sessions use hardened cookies;
- mutating requests use CSRF-aware client logic;
- passwords are stored as hashes;
- Helmet and rate limiting are enabled;
- secrets are loaded from local `.env*` files, not from Git.

Границы изменений (с 05.11.2026):

- Прежняя версия симуляции («Космонавт» и ЗРД: `client/`, `server/`, `shared/`, `migrations/`, база SQLite) не затрагивается работой над картой проекта и паспортом. Её меняют отдельными PR по отдельным задачам.
- Дорожная карта лежит в `docs/project/roadmap-tool/` и не входит в сборку приложения: это статичные файлы и два скрипта (`build.py`, `mkxlsx.py`). Она не импортирует код симуляции, не читает её базу и не вызывает `/api/*`.
- Новый продукт по паспорту (критерии отбора, форма обратной связи, цифровая платформа) на момент записи не начат. Когда начнётся, его границы с прежней версией описываются здесь отдельным разделом до первого коммита кода.
