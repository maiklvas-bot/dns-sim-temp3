# Гигиена папки проекта

Правило проекта. Действует для людей и для агентов схемы (`docs/project/claude-headquarters.md`).

## Что лежит в корне, а что нет

- В корне только то, что относится к самому приложению и к его запуску. Скриншоты проверок, выгрузки, дубли файлов и черновики в корень не кладём.
- Временные файлы, скриншоты и дампы кладём в `tmp/` (в git не попадает). Артефакты, которые нужны команде, живут в `docs/project/<тема>/`.
- Один файл — одно место. Если копия нужна в корне для удобства, её добавляют в `.gitignore`, а оригинал лежит в `docs/`.
- Каталоги `script/` (рабочие скрипты TypeScript и проверки) и `scripts/` (shell-скрипты деплоя) — разные вещи, `scripts/` не удалять и не сливать со `script/`.

## Секреты

- В репозитории и в любых архивах не бывает `.env`, `.git-token-store`, `.mcp.json`, `data.db` и ключей. Токен и файл с токеном агенты не читают и не копируют.
- `.git-token-store` перечислен в `.gitignore`, чтобы новый клон не вынес его в коммит.

## Архив для передачи

- Архив собирается из git, а не из папки: `git archive --format=zip -o <имя>.zip HEAD`. Так в него не попадают `.env`, токен, база, `node_modules`, `dist`, скриншоты и `tmp/`.
- Тяжёлые медиа (`attached_assets/`, `uploads/`) входят в архив только если получатель просил их; в имени архива указывают короткий хеш коммита.
- Перед отправкой наружу архив проверяет владелец: отправка в почту, мессенджер или на Диск — только по его «да».

## Чистка

- Удаление файлов вне git (скриншоты, `tmp/`, `.worktrees/`, `dist/`) — только по отдельному «да» владельца на конкретный список.
- Временные каталоги не коммитим. Если такой каталог попал в git, его убирает отдельный PR.
