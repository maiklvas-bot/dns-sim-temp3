**Как собираются данные о провале критичной компетенции? Какие условия должны совпасть, что участник должен сделать, чтобы компетенция провалилась?**

По компетенции считается средний балл всех решений, где она проверялась. Если среднее
оказалось ниже 2,0 из 5 — срабатывает красный флаг. Провал по критичной компетенции
не закрывается высокими баллами по остальным, в этом и смысл.

Критичных пять: планирование, контроль, ответственность, коммуникация, ориентация
на результат.

Чтобы было понятнее, возьму «Контроль» — он проверяется в пятнадцати решениях
за прохождение. Посчитал на реальных данных, сколько раз надо выбрать слабое
поведение, чтобы получить флаг:

| Слабых решений из 15 | Если остальное «средне» | Если остальное «сильно» |
|---|---|---|
| 8 | 1,93 — провал | 2,87 — норма |
| 11 | 1,53 — провал | 2,07 — норма |
| 12 | 1,40 — провал | 1,80 — провал |
| 15 | 1,00 — провал | 1,00 — провал |

Флаг ставится за устойчивую линию поведения, а не за одну неудачу. Нужно выбрать
слабый вариант примерно в 8–12 случаях из 15. Одна или две ошибки на прохождение
флага не дают.

**Тут нашлась ошибка.** Порог 2,0 сейчас применяется к неверно посчитанному числу.
При сведении оценок в итог слабый ответ штрафуется дважды: он уже размечен единицей,
и сверх этого домножается на «качество варианта».

В реальных прохождениях «Контроль» получал итог 0,4 — при том что минимум шкалы
равен 1. Ниже единицы оценок по правилам быть не может.

Значит флаг срабатывает чаще, чем задумано, и часть кандидатов могла получить
пометку несправедливо. Это первое, что надо исправить.

И есть вторая проблема. Чтобы доверять среднему баллу, компетенцию нужно увидеть
в разных ситуациях, а не много раз в одной. Сейчас так:

| Критичная компетенция | Решений за прохождение | В скольких разных кейсах |
|---|---|---|
| Коммуникация | 29 | 11 |
| Планирование | 28 | 10 |
| Контроль | 15 | 5 |
| Ответственность | 11 | 5 |
| Ориентация на результат | 9 | 3 |

Ориентация на результат проверяется всего в трёх ситуациях. Флаг по ней — повод
для разговора, но не основание для отказа. Сейчас в отчёте он выглядит так же
уверенно, как флаг по коммуникации с одиннадцатью кейсами. Это надо показывать явно.

---

**Правильно ли понимаю, что теперь будет 3 варианта ответа?**

Нет, вариантов остаётся пять, как и было. Тройка — про другое, тут легко перепутать
две разные вещи.

Проверил по базе: во всех девяноста циклах, включая обновлённый комплект, ровно
по пять вариантов ответа. Кандидат по-прежнему выбирает из пяти.

Три — это уровни оценки компетенции. Каждый вариант получает по каждой компетенции
одну из трёх оценок: слабо — 1 балл, средне — 3 балла, сильно — 5 баллов.

В обновлённом комплекте 354 оценки «слабо», 285 «средне», 261 «сильно».
Промежуточных 2 и 4 нет вообще — раньше они встречались, но смысла не несли,
просто повторяли номер варианта.

Меняется только то, как автор размечает варианты и что видит асессор в отчёте.
Для кандидата на экране ничего не меняется: те же пять вариантов.

---

**Оценки от «слабо» к «сильно» применимы к кейсу или компетенциям?**

К компетенциям, причём внутри каждого варианта ответа отдельно. Один вариант может
быть сильным по планированию и слабым по коммуникации одновременно. У кейса как
целого своей оценки «слабо/средне/сильно» нет.

Вот настоящий пример из кейса «Утренняя расстановка смены»:

> «Раздать участки самому: Дима на склад, Света на кассу, Ксения на выдачу,
> Артём в зал. Открываемся вовремя.»

| Компетенция | Оценка |
|---|---|
| Планирование | сильно |
| Контроль | сильно |
| Коммуникация | слабо |
| Делегирование | слабо |

Читается прямо: сделал всё сам и молча. Магазин откроется вовремя, но люди остались
без задач и без практики. Вот это и есть материал для разговора с кандидатом
на разборе.

Как раз это и было сломано раньше. В старом комплекте 91% вариантов ставили одно
и то же число всем своим компетенциям сразу. Был вариант, где двенадцать компетенций
получили по пятёрке разом.

При такой разметке оценка компетенции не говорит о компетенции. Она просто повторяет,
какой это по счёту вариант в ряду от слабого к сильному. Разбирать нечего: все числа
одинаковые. В обновлённом комплекте таких вариантов 9% вместо 91%.

**Можно ли посмотреть, как будет выглядеть панель «показатели магазина»? Хотя бы схематично.**

Схематично — ниже. Коротко: приборная панель уходит с экрана прохождения, вместо
неё после каждого решения показывается написанный автором текст о том, чем кандидат
заплатил за свой выбор. В итоговом отчёте показатели остаются.

Сейчас, правая колонка экрана:

```
┌─────────────────────────────┐
│  ПОКАЗАТЕЛИ СМЕНЫ           │
│  Покупатели в зале      18  │
│  Средний чек       7 200 ₽  │
│  Конверсия             48%  │
│  Клиентская оценка     4,5  │
│  Скорость выдачи    12 мин  │
│  Загрузка склада       40%  │
│  Настроение команды    7,0  │
│  Выручка за день   1 500 ₽  │
└─────────────────────────────┘
```

Плюс слева карта зон магазина с теми же данными в виде графиков. Вместе занимают
около 40% ширины экрана.

Предлагается, окно после решения:

```
┌────────────────────────────────────────────┐
│  ЦЕНА ВЫБОРА                               │
│                                            │
│  Быстро и точно, магазин откроется         │
│  в срок. Но всё держится на вас:           │
│  Артём в третий раз подряд не получает     │
│  практики принимать решения.               │
│                                            │
│                              [ Дальше ]    │
└────────────────────────────────────────────┘
```

Текст написан автором под каждый конкретный вариант ответа, а не подобран
автоматически.

Почему предлагаю именно так:

- Текст уже написан. У всех 225 вариантов обновлённого комплекта есть авторское
  объяснение цены выбора. Оно доходит до браузера кандидата, но показывается только
  автору кейса при подготовке материалов.
- Сейчас вместо него случайная фраза. Кандидат видит одну из 48 универсальных
  заготовок, одинаковых для любого решения в любом кейсе. К его конкретному выбору
  она отношения не имеет.
- Панель почти ничего не добавляет. На обновлённом комплекте в 88 случаях из 100
  показатели просто повторяют то, что и так видно по оценке компетенций.
- Один показатель считается наоборот. Рост очереди улучшает «скорость выдачи»
  на экране, хотя должен ухудшать. У 38% вариантов, где очередь растёт, система
  рисует зелёную строку «выдача ускорилась» — даже для худшего ответа в кейсе.

Сам расчёт показателей никуда не девается: он остаётся в итоговом отчёте и помогает
различать варианты, когда оценки по компетенциям одинаковые. Уходит только приборная
панель во время прохождения.

Если по схеме непонятно, могу собрать кликабельный макет обоих вариантов к четвергу —
посмотреть вживую.

---

**Относительно компетенций в одном кейсе много вопросов, предлагаю предметно обсудить в четверг.**

Согласен, тема требует разговора. Коротко моя позиция: ограничивать число компетенций
не нужно — сейчас их четыре на кейс, это нормально. Нужно требовать, чтобы оценки
внутри варианта различались.

К встрече подготовлю:

- распределение всех компетенций по кейсам с числами;
- разницу между ограничением на вариант и на кейс — это разные вещи с разными
  последствиями;
- расчёт, сколько кейсов нужно для надёжной оценки каждой компетенции;
- предложение по правилу разброса оценок вместо ограничения количества.

Настоящей проблемой была неразличимость оценок, а не их количество. Когда все
компетенции варианта получают одно число, не помогает ни сокращение списка,
ни его расширение.

---

**Что ещё стоит обсудить в четверг?**

Двойной штраф в подсчёте, о котором я написал в первом вопросе. Это не косметика.

Флаг о провале критичной компетенции сейчас срабатывает по искажённой цифре. Значит,
часть кандидатов могла получить пометку несправедливо.

Нужно решить: пересматривать прошлые результаты или считать их несопоставимыми
целиком. Склоняюсь ко второму — там ещё и старый комплект кейсов с неразличимыми
оценками, так что сравнивать те прохождения с будущими всё равно нельзя.
