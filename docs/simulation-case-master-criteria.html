03 · Стоп-факторы

Правило: компетенция становится стоп-фактором, если её отметило большинство управляющих (>n/2). На n=43 порог = 22 из 43.

Стоп-фактор

Организация и контроль работы — 24 / 43 (было 18/36, точная граница). Рост выборки снял вопрос: теперь впереди по частоте.

Стоп-фактор

Направленность на результат — 23 / 43 (было 19/36). Строгое большинство на обеих выборках.

Не проходит порог

Системность мышления 16/43 · Бизнес-процессы 15/43 — важны по весу, но не стоп-факторы.

Механика — мягкое вето. Симуляция не останавливается. Стоп-фактор проверяется по агрегированному баллу компетенции; если он ниже порога θ (ориентир <2 из 5) — красный флаг: блокирующее условие развития, а не «незачёт».

04 · Модель компенсации

Два слоя. Подтверждено на конкретном примере пользователя: слабое планирование и сильный контроль — видно раздельно, но стоп-флаг решается по свёртке.

Слой A

Внутри компетенции

«Организация и контроль работы» раскладывается на 3 подпризнака: планирование / постановка задач / контроль. Каждый виден автору кейса и в дебрифе отдельно — слабость одного не прячется молча.

Слой B

Между 14 компетенциями

Итог сессии = взвешенная сумма всех компетенций, кроме стоп-факторов. Сильная сторона в одной естественно перевешивает слабую в другой — но стоп-факторы в эту сумму не подмешиваются.

06 · Дебриф — уровень сессии

Архитектурное решение: дебриф собирает сигналы со всех кейсов и каналов сессии, а не с одного кейса.

Дебриф строится поверх уже существующего в движке среза SessionResultPayload.competencyAverages — не требует новой модели агрегации с нуля.

Структура. Факты / Логика / Диагностика / Риски / Люди / Перенос — вопросы генерируются под конкретные слабые компетенции профиля.

При красном флаге. Обязателен углублённый разбор именно этой компетенции — отдельным блоком, не общим вопросом.

Закрытие флага. План мероприятий + повторная проверка. Навык закрыт только после подтверждённого повторного наблюдения.

07 · Автопроверка мастера

Мастер не даёт кейсу перейти дальше по статусу, пока не пройдены все четыре.

1

Соответствие Мерилу

Автор выбирает уровень BARS, а не вводит число вручную — балл выводится автоматически из уровня × вес.

2

Антигейминг

Векторы компетенций вариантов внутри цикла не должны быть строго ранжируемы — иначе это одна «шкала хорошести».

3

Наличие диагностики

Скрытая причина, данные и ложные следы должны быть заполнены — кейс не проходит без них.

4

Реальность эффектов

У каждого варианта хотя бы одно поле состояния должно измениться — decorативные варианты блокируются.
