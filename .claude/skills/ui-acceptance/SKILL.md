# Приёмка интерфейса

Полные правила и причины — в `AGENTS.md`, раздел «Правила интерфейса». Здесь список для проверки. Любой пункт, который не выполнен или не проверен, называется в отчёте.

1. **Цвет только токеном.** Палитра берётся из `client/src/styles/tokens.css`. Цвета на месте не подбирать, кабинеты семантические токены не переопределяют. Произвольный серый вне бренд-палитры не допускается; красный только для реальных рисков. Проверка: `npm run test:ui`.
2. **Всплывашки порталом.** Подсказка, поповер, тултип, меню рендерятся через `client/src/components/floating-card.tsx` в `body`, с `position: fixed`. Не `absolute` внутри панели: `overflow` родителя обрежет, `z-index` не поможет. Координаты окна: `clientX/clientY` или `getBoundingClientRect()`.
3. **Высота измеряется.** Вычитаемое вида `calc(100dvh - 19rem)` под шапку не подбирать.
4. **Состояния по действию.** Каждое состояние, которое появляется при наведении, клике, раскрытии, проверяется отдельно: навести, кликнуть, снять. Скриншота одного статичного вида недостаточно.
5. **Viewport как у окна.** В Playwright размер окна равен реальному, иначе страница выглядит обрезанной при целой вёрстке.
6. **Плитки одного размера.** Наборы карточек: `grid auto-rows-fr` и `h-full` на карточке, одинаковая анатомия. Без разнокалиберных `col-span`; не поместившееся выносится полосой под сеткой.
7. **Проверки.** `npm run check`, `npm run test:ui`, `npm run test:browser`, `npm run build` по тому, что затронуто; в отчёте команда и код возврата.

Если проверить по-настоящему нельзя (нет браузера, нет стенда), так и написать: «не проверено: что именно и почему».
