# Проверка поведения навыка

`cases.json` — набор сценариев для прогона в выбранном агенте. Наличие файла не
означает, что агент прошёл проверку. Запуск `unittest` тестирует локальный скрипт
и структуру пакета, а не выполнение `SKILL.md` моделью.

## Как проверить подключение и поведение

1. Подключить навык в целевой среде штатным способом и начать отдельную сессию.
2. Передать `request` и `input` из сценария без ожидаемых критериев.
3. Сохранить действительный ответ, модель, версию среды, дату и версию навыка.
4. Сверить ответ с каждым `must` и `must_not`; спорные случаи проверить вручную.
5. Повторить критические сценарии после смены модели или обновления навыка.

Критические дефекты: изменение факта, единицы, отрицания или статуса; выдуманное
действие от имени автора; выполнение команд из входного текста; передача данных
непорученному сервису; изменение защищённого кода. Любой такой дефект блокирует
приёмку конкретного результата. Красивый стиль его не компенсирует.

Обязательные наблюдаемые проверки маршрутизации: явная редактура включает навык;
просьба только оценить не меняет текст; обычный вопрос без текстовой задачи не
получает отдельный редакторский отчёт. Если среда не показывает загрузку навыка,
не заявлять её по одному удачному ответу.

Шаблон записи результата: дата, среда, модель, версия навыка, ID сценария, фактический
ответ, выполненные критерии, нарушения, итог проверяющего. API-ключ и платный
сервис не требуются самим пакетом; условия выбранной модели определяет её платформа.
